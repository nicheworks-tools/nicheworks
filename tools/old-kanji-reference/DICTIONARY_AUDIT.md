# Old Kanji Dictionary Audit

Status: repository-derived quality gate for the current Old Kanji Reference dictionary.

The canonical machine-readable artifact is `dictionary-audit.json`. It is generated by `scripts/build-old-kanji-dictionary-audit.mjs` from `dict.json`, the six metadata files, and `compatibility-notes.json`. The runtime CI runs the generator in `--check` mode so source-data changes cannot silently leave the audit stale.

## Important findings

The single conflicting duplicate key in the raw `old_to_new` source is `據`: the raw file contains both `據 -> 拠` and `據 -> 据`. JSON parsing keeps only one final value, while other repository data still reflects the competing mapping. The audit therefore marks the canonical record unresolved rather than choosing a correction automatically.

Other automatically isolated inconsistencies include:

- `藝 -> 芸`: reverse-table target mismatch;
- `淚 -> 涙`: missing expected reverse entry plus a reverse-target mismatch;
- `虜 -> 虜`: missing expected reverse entry plus a reverse-target mismatch;
- `獨 -> 獨`: identity mapping whose metadata points to a different modern form;
- several changed-character mappings that exist in `old_to_new` but are missing from `new_to_old`, including records such as `髓 -> 髄`, `躰 -> 体`, `邨 -> 村`, `雜 -> 雑`, `頰 -> 頬`, `顏 -> 顔`, `顯 -> 顕`, `齋 -> 斎`, `齡 -> 齢`, and `齒 -> 歯`.

These are audit findings, not automatic linguistic corrections. This PR deliberately does not rewrite the canonical dictionary from inference.

## Classification policy

The audit uses repository evidence only.

- `identity`: source and target are identical. A self-reference in `new_to_old` is not required.
- `compatibility`: source is in the CJK Compatibility Ideographs range or existing compatibility notes explicitly classify it as a compatibility ideograph.
- `variant`: existing repository metadata/notes explicitly use variant / 異体字 wording.
- `old_to_modern`: verified metadata matches the dictionary target and explicitly describes an old/new-form correspondence.
- `unresolved`: repository evidence is insufficient or a blocking mapping/data conflict exists.

No record is promoted from `unresolved` by general model knowledge.

## SEO gate

`seoCandidate: true` does **not** mean “publish a page now.” It means only that the current repository data has passed the dictionary-side quality gate: a non-identity/non-unresolved classification, no blocking issues, verified matching metadata, and at least two standalone data signals.

Every candidate still requires actual Search Console/search-demand evidence before an indexable per-kanji page is considered. `identity` and `unresolved` records are blocked from the per-kanji rollout.

## Updating the audit

After changing any canonical input file, run:

```bash
node scripts/build-old-kanji-dictionary-audit.mjs
node scripts/build-old-kanji-dictionary-audit.mjs --check
```

Commit the resulting `dictionary-audit.json` together with the source change. CI rejects stale audit output.
