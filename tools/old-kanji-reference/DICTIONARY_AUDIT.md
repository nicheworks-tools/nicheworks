# Old Kanji Dictionary Audit

Status: current data-quality gate for the Old Kanji Reference dictionary.

The canonical machine-readable artifact is `dictionary-audit.json`. Runtime CI runs the generator in `--check` mode so source-data or audit-policy changes cannot silently leave the artifact stale.

As a result, `unresolved` falls from 55 to **51**, `old_to_modern` rises from 163 to **165**, and `variant` rises from 1 to **3**. The SEO-candidate count stays **168** because authoritative relation evidence does not waive the separate verified-metadata / standalone-value gate.

## Maintenance disposition policy

Every remaining anomaly entry in `dictionary-audit.json` now carries one of three explicit dispositions: `fix`, `intentional`, or `deferred`.

### Raw duplicate keys — 8 `fix`

The remaining duplicate keys are:

`舉`, `藝`, `擊`, `覽`, `藥`, `雙`, `禍`, `護`

All eight duplicate occurrences currently repeat the **same value**; there are no conflicting duplicates. Their runtime parse result is therefore stable. They remain `fix`-class source-cleanup debt because duplicate object keys are undesirable even when same-valued. Removal is mechanical and must preserve the effective mapping exactly.

### Metadata overlays — 61 `deferred`

The six metadata layers intentionally load in a defined order and later files currently override earlier entries. The audit records every overlap with previous/next source provenance. There are **61 overlay events across 58 distinct keys**.

These are not automatically data errors. They are `deferred` because consolidating or removing an overlay requires field-level semantic comparison. Until that review is performed, the ordered last-file-wins behavior remains explicit and testable rather than being silently normalized.

### Unresolved canonical records — 51 `deferred`

All 51 remaining unresolved records are character-changing mappings with no blocking structural issue but insufficient current repository evidence to promote them to `old_to_modern`, `variant`, or `compatibility`.

They remain usable only according to the existing runtime/reference boundary and are explicitly blocked from per-kanji SEO publication. Promotion requires authoritative relation evidence; model knowledge, normalization heuristics, or visual similarity are not sufficient.

The machine artifact enumerates all 51 records individually and records the same maintenance disposition/reason on every unresolved record.

## Classification policy

Classification precedence is:

1. blocking data-quality conflict → `unresolved`;
2. identity mapping → `identity`;
3. matching authoritative PR8 repair evidence → its supported relation class;
4. compatibility evidence → `compatibility`;
5. repository variant wording → `variant`;
6. verified repository old/new-form metadata → `old_to_modern`;
7. otherwise → `unresolved`.

Supported authoritative repair relations are deliberately narrow:

- `old_to_modern` → `old_to_modern`;
- `variant` / `semantic_variant` → `variant`;
- `unicode_compatibility` → `compatibility`.

A repair-ledger record is ignored for classification if its `afterTarget` no longer equals the current dictionary target.

No record is promoted from `unresolved` by general model knowledge.

## SEO gate

`seoCandidate: true` does **not** mean “publish a page now.” It means only that the repository-side dictionary/data gate has passed: the record is non-identity/non-unresolved, has no blocking issues, has verified matching metadata, and has at least two standalone data signals.

Every indexable per-kanji page additionally requires actual Search Console/search-demand evidence and authoritative source support. `identity` and `unresolved` records remain blocked. The current allowlist contains only the separately approved pages documented by `tools/OLD_KANJI_CLUSTER.md`.

## Updating the audit

After changing any canonical input or the audit generator, run:

```bash
node scripts/build-old-kanji-dictionary-audit.mjs
node scripts/build-old-kanji-dictionary-audit.mjs --check
```

Commit the regenerated `dictionary-audit.json` together with the source or policy change. CI rejects stale audit output.
