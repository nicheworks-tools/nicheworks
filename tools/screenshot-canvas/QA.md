# Screenshot Canvas QA — automated and manual scope

## Automated Chromium checks

- [x] Import two PNG images through the file selector.
- [x] Decode JPEG and WebP generated by Chromium.
- [x] Drag-and-drop an image into the workspace.
- [x] Paste an image through a browser ClipboardEvent.
- [x] Reject non-image files, oversized inputs and corrupt PNGs without losing existing layers.
- [x] Reject 12,000×12,000px (144MP) canvas allocation, preserving the previous 1600×900 composition.
- [x] Allocate/render an allowed 6000×4000 (24MP) canvas in desktop Chromium, refuse 6000×4001, undo safely and recover from a failed PNG encoder.
- [x] Verify layer picker, multi-select, foreground/background ordering.
- [x] Move an image with pointer events and simulated touch-type PointerEvents.
- [x] Resize from all four corner handles and undo each resize.
- [x] Keyboard-select a layer, use Shift+Arrow to move, Ctrl+Z and Delete.
- [x] Reach the file input using keyboard focus (input is visually hidden, not display:none).
- [x] Test row, column, grid, overlay, opacity, canvas dimensions, background, undo and redo.
- [x] Check PNG export filename, MIME type, pixel color and transparent background.
- [x] Switch between Japanese and English without losing controls.
- [x] Check page overflow at 1440px, constrained 390px and 360px widths.

Run: `node tools/screenshot-canvas/tests/browser-smoke.mjs`.
CI: `.github/workflows/screenshot-canvas-browser-smoke.yml`.

## Not certified by browser automation

- [ ] Physical Android/iOS finger gestures and OS clipboard integration.
- [ ] Full screen-reader compatibility and platform assistive-technology review.
- [ ] Stress-test **allowed** high-resolution canvases (up to 24MP) on low-memory physical devices; a 144MP rejection is covered by Chromium, not hardware pressure.

Synthetic touch events are not equivalent to physical-device confirmation. All remaining items are documented follow-ups; none requires the user to perform work immediately.
